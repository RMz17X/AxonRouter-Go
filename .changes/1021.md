# 1021 — Account verification state: visible in the UI, clearable by recheck

## Symptom
- An antigravity account hit by Google's "Verify your account to continue.
  PERMISSION_DENIED VALIDATION_REQUIRED" demand was parked as a generic
  "disabled" row: the stored verification URL never surfaced, nothing
  showed whether the operator had already verified the account upstream,
  and the probe path refused to re-check it at all — persistProbeResult
  and testSingleConnection treat any stored "disabled" verdict as
  terminal (fragment 973), and a validation row carries
  testStatus "disabled", so even after verifying at Google the account
  stayed parked until a manual reset-status.

## Root cause
- The validation state existed only as scattered data keys
  (status "validation_required", verificationUrl, lastError) with no
  health state of its own: the client derivation folded it into
  "disabled", and the probe persister could not distinguish the
  recoverable validation verdict from a terminal ToS disable.

## Fix
- Probe path (internal/handlers/dashboard/connection_probe.go):
  storedDisabledMessage no longer treats status "validation_required"
  as terminal (the status field is the canonical verdict — both disable
  writers set status "disabled"; testStatus alone now only counts for
  legacy rows without a status). persistProbeResult: when a
  validation-flagged connection probes valid, the flag is cleared
  (status/verificationUrl/validationMessage/validationAt deleted) and
  the connection is reactivated via SetConnectionStatus(true) — the
  "verified" transition, proven by the upstream accepting the account.
  A probe that fails again keeps the flag.
- Dashboard: connectionHealth derives a distinct "validation" state
  (verificationUrl present, or a disabled verdict whose lastError
  carries the validation markers) ahead of "disabled"; the account
  status strip gains a "Needs verification" segment; the provider
  detail row shows a "needs verification" badge with a Verify link
  (the stored Google URL, manual click) and a Recheck button that
  re-probes the account and refreshes the row.
