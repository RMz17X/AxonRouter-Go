### Fixed
- The antigravity in-flight cap of 3 per account (v1.10.63) was still too loose for production traffic: the post-flip census read 89 failed gemini-3.8-flash requests against 3 successes in 14 minutes, because a production generation is a large streaming request that occupies its account for tens of seconds and any overlap draws the bare RESOURCE_EXHAUSTED 429 — the few successes clustered in the low-concurrency window right after the provider breaker closed, when attempts happened to run one at a time. The cap is now 1: strictly sequential per account, the same shape a single interactive Antigravity user produces (which is known to work), with parallelism coming from rotation across the account pool instead of stacking on one account.
