### Removed

- **Credential vault (envelope encryption at rest) removed; the Security page is now Guardrails only.** The vault was opt-in via `ROUTER_MASTER_KEY` and disabled on the staging install (status: `enabled:false`, 0 sealed / 19 plaintext connections), so it added a master-key failure mode — lose the key, lose every sealed credential — without protecting anything in practice.

**Symptom.** The dashboard's Security page mixed two unrelated systems: an opt-in credential vault (status card, sealed/plaintext counters, master-key rotation) and the guardrail policy engine. The vault was off unless an operator set `ROUTER_MASTER_KEY`, and its seal/hydrate passes sat on every provider-connection read and write.

**Root cause.** The F-5 vault was built as an optional layer: with no master key it degraded to plaintext pass-through, so the fleet ran unsealed while the UI, routes (`GET /api/vault/status`, `POST /api/vault/rotate`), boot migration, and per-write sealing code all stayed in the tree. The owner ordered the system deleted outright rather than enabled.

**Fix.**
- Backend: deleted `internal/vault/`, `internal/db/vault.go` (seal/open call sites, sealed-slot schema columns), `internal/db/vault_migrate.go` (boot-time plaintext-sealing pass), and `internal/handlers/dashboard/vault.go` with both vault routes in both routers. `Repo` no longer carries a vault; connection writes (`CreateProviderConnection`, `CreateProviderConnectionFull`, `ReplaceProviderConnectionPayload`, `UpdateConnectionData`, importer writes) store the `data` payload directly and reads return it as stored — the same plain form a vault-less install always used. The six sealed columns are no longer added to fresh schemas (existing databases keep the now-unused columns; nothing reads them). The vault-only test files went with the feature.
- Guardrails are untouched: policies, audit logs, prompt scanning, and the `guardrailsEnabled` setting behave exactly as before.
- Frontend: the panel loses the vault section (status card, sealed/plaintext summary cards, rotation form and confirm dialog) and the `getVaultStatus`/`rotateVault` API client methods. `SecurityPanel.svelte` is renamed `GuardrailsPanel.svelte`; the tab id `security` becomes `guardrails`, the sidebar label and page titles read "Guardrails", the canonical route is `/dashboard/guardrails`, and the old `/dashboard/security` + `/security` paths remain as legacy aliases. Saved nav preferences carrying the old id are dropped by the existing unknown-id filter, so no preference migration is needed.

**Verification.** `go build ./...` green; `go vet` clean on the touched packages (`internal/db`, `internal/app`, `internal/handlers/...`); web build green; svelte-check at the standing baseline (89 errors / 56 warnings). No `vault` references remain in Go or web sources outside historical changelog/fragments and planning docs. Live staging check before removal: vault disabled, zero sealed rows — so no stored credential is stranded by the removal and no data migration was required.
