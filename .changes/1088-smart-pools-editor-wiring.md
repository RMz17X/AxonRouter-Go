### Fixed
- **Smart Pools editor in the combo modal now loads and saves the stored Easy/Hard pools.** The parent passed the pools under prop names the modal does not declare (`initialEasyModels`/`initialHardModels`/`initialRouterModel`) and never passed the update callbacks, so the editor always opened with empty pools (header "0 Easy / 0 Hard / N Auto") even when the combo's strategy stored assignments — and the router model never loaded either. The parent now passes `easyModels`/`hardModels`/`routerModel` backed by its modal state and wires `onUpdateEasyModels`/`onUpdateHardModels`/`onUpdateRouterModel`, so Edit opens with the real pools and Save persists them through the strategy merge.
- **The per-row Easy / Hard / Auto tier toggles work.** They called a `toggleModelTier` handler that was never implemented, so clicking a tier button threw and changed nothing. The handler is implemented on top of the existing pool movers: selecting a tier moves the model into that pool, re-selecting the active tier (or choosing Auto) returns it to the unassigned set, and the model itself always stays in the combo.
- Removed the modal's dead pool helpers (remove/reorder functions no template referenced) and an unused icon import, and fixed the "Add Models Manually" button passing the click event where a picker target was expected. svelte-check is back to 0 errors / 0 warnings.
