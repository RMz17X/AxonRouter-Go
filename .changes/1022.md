# 1022 — Provider header: status chips beside the connection count; group bindings resolve to the group name

## Symptom
- The account status summary (Active / Needs verification / Error /
  Cooldown / Locked / Disabled counts) rendered as its own row above
  the connections list, while the provider header counted the same
  connections separately ("371 connections") — the operator asked for
  the chips beside that header count.
- The proxy-resolution readout enumerated the matched pools for a
  group/type binding ("Resolves to 378 active pools: relay-…-1,
  relay-…-2, relay-…-3 +375 more") — at group scale the pool list is
  noise; the operator picked the group, so the readout should name it.

## Fix
- ProviderAccountStatusStrip gains a showCount prop (default true);
  ProviderDetailView now renders the strip in the page header's meta
  row, right after the "{n} connections" label, with showCount off,
  and the standalone instance above the connections list is removed —
  the summary has exactly one home, beside the count it describes.
- ProxyResolutionNote: for binding kinds group / type / multi the
  resolving line now names the selector ("Resolves to proxy group:
  cloudflare." / "proxy type: …" / "proxy groups: A, B"), derived from
  the normalized selector with group:/type: prefixes stripped and
  bare pool parts resolved to display names via the candidate list.
  Single-pool bindings keep the pool enumeration; the no-match warning
  is unchanged.
