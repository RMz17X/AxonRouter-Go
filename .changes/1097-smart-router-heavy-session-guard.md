### Fixed
- The smart router no longer judges a turn by its wording alone. It previously evaluated only the latest user turn (truncated to 2000 chars), so a two-word steering message ("go on", "fix that") in the middle of a long, heavy coding session read as a trivial standalone request and could lead the chain with an easy-tier free model — and a Smart Switch re-evaluation could actively demote a pinned strong model on exactly such a turn. The gateway now computes a deterministic session view from the body it already holds (message count, conversation text size, tool definitions/calls/results, a tool-result last turn): a session counts as heavy when tools are in use or its text exceeds 48K chars. In a heavy session an easy-tier member (operator-listed, else name heuristics) may no longer lead the chain — every ordering the strategy returns (fresh choice, smart-switch, strict pin, fallback order) demotes easy members to the tail, where they remain as fallback, so the guard can never fail a request that would otherwise succeed. The state sent to the router model is enriched with the same view: a one-line session summary plus the three most recent user turns, so the decision model itself can see that a short turn belongs to a long tool-driven session. The body is parsed once and the view rides the request context, so evaluation does not parse it again.
