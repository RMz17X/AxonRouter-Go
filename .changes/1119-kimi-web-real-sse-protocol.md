Every kimi-web reply was prefixed with a mangled fragment of the user's own prompt ("Say one short sentence about t" + the answer). Root cause, proven by a raw capture of the real stream on 2026-11-11: Kimi's SSE protocol names each event in an `event` field, not the `type` field the spec's section 6 invented — the executor's classifier keyed on `type`, so no real event ever matched a named case, and every answer delta arrived only via the lenient default branch that folds any text-bearing event into the content. That same default also folded in the `rename` event, whose `text` is the auto-generated chat title (the prompt's head, truncated), and the stream's end signal is `done`, not `all_done`. The classifier now keys on `event`: only `cmpl` carries answer text (a `think` view routes to reasoning — defensive, no thinking model probed live yet), `done` finishes the turn, an `error` event fails it, and all furniture events (`req`, `resp`, `ping`, `zone_set`, `loading`, `rename`, anything unlisted) are ignored whatever their other fields hold. The test fake now replays the captured wire shape, including the title event as a leak trap, and the spec's section 6 is rewritten to the real protocol.
