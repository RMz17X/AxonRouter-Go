### Fixed
- The quota tracker's search now runs against the whole database in SQL instead of over a full-table load filtered in memory (operator report: an account outside the loaded slice could never be found — in particular, accounts whose only identity is the displayName stored in `data` were invisible to the old matcher, which looked at name/email/provider only). `GET /api/providers/client` (and `/api/providers`) now goes through `Repo.GetClientUsagePage`: eligibility, provider, account-status and search are WHERE clauses, the three response totals are COUNTs at each filter level, and only the requested page is read back, ordered exactly as the previous in-memory sort (eligibility-list provider grouping, then provider, priority with nil = 0, name) plus a final `id` tiebreak so page boundaries are stable. Search covers the upstream field set — name, email, connection id, provider, and `data` displayName/username/githubLogin — matched as a literal case-insensitive substring (LIKE wildcards in the query are escaped, preserving the old matcher's literal semantics; upstream interpolates them unescaped). The fatal-disable sweep that used to ride on this endpoint's full-table load keeps its reach through a targeted candidate query keyed on the shared `db.FatalDisableErrorSignatures` list, re-checked with the exact Go predicate. This also removes the per-request cost the old shape imposed on the §4.G box: every page fetch previously hydrated and deep-cloned the entire providerConnections table (38K+ rows with `data` blobs) from the snapshot cache just to return 20 rows.
